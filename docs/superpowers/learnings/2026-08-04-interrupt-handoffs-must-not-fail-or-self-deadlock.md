# Interrupt Handoffs Must Not Fail or Self-Deadlock

**Date:** 2026-08-04
**Context:** OmniHarness direct conversations, queued messages, live elicitation answers, and user steer recovery
**Symptom:** Session `8d81f64ca066` showed “asking for your input,” then stayed “working” after the user sent `yes fix`. The run was actually failed, two queue rows were stuck in `delivering`, and the UI treated those orphaned rows as ongoing work.
**Root Cause:** The queued answer to a live elicitation tried to acquire the per-worker turn gate already held by the turn waiting for that answer, creating a self-deadlock. The later steer correctly aborted the old turn, but both initial-turn catch handlers classified the intentional `WorkerTurnAbortedError` as a crash and emitted `run_failed`. A second abort path returned without releasing its claimed queue row.
**Fix:** Deliver live elicitation answers directly to their owning turn instead of queueing behind it; classify intentional initial-turn aborts as expected handoffs; and always close or requeue a delivery row when a newer steer aborts or supersedes it. The affected session was resumed from its saved Claude session, its already-delivered `yes fix` row was reconciled by exact message id, and the stale recovery incident was resolved without redelivering the reply.
**Verification:** Red-green regressions passed in `tests/server/conversations/create-steer.test.ts`, `tests/server/queued-message-interrupt.test.ts`, and `tests/server/queued-messages.test.ts` (24 tests total). The headless lifecycle scenario `tests/lifecycle/scenarios/direct-initial-steer.test.ts` passed in isolation. `pnpm typecheck` and `git diff --check` completed successfully.
**Prevention:** Model stop/steer as an ownership transfer with explicit terminal handling for the old owner. Never acquire a resource gate from work that is already waiting inside that gate. Require every claimed queue state to have a terminal or retry transition on success, failure, abort, supersede, and restart.
**Skill/Doc Updates:** Updated `docs/architecture/lifecycle-observability-and-testing.md` with the intentional-abort, queue-release, and live-elicitation gate invariants. No global skill change was needed because the existing control-plane and client/server-state skills already require explicit ownership, terminal states, and observable decisions.
