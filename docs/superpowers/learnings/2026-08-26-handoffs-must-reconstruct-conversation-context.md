# Handoffs Must Reconstruct Conversation Context

**Date:** 2026-08-26
**Context:** OmniHarness cross-CLI handoff capture and mobile handoff dialog
**Symptom:** A handoff preview repeated the latest user message as the objective and remaining work, while the useful earlier assistant discussion was absent. The latest assistant "summary" was only a quota-limit response.
**Root Cause:** Candidate gathering treated the newest worker stream as the whole conversation. Replacement workers split one conversation across several append-only streams, so the newest stream could contain only the final user turn and a provider error. The synthetic advisory then copied the latest objective into remaining work, making the loss look like duplicated content.
**Fix:** Build bounded evidence exclusively from persisted conversation messages plus recent visible entries across the run's worker streams, deduplicate replayed entries, and reject quota/auth failures as assistant context. Keep message-fork boundaries scoped to the selected worker stream. Source-worker prompting was removed entirely. A disposable read-only instance of the selected target CLI now converts the evidence into structured advisory fields, while the real target receives compact Markdown instead of packet JSON. The advisory no longer invents remaining work by repeating the objective, and the verbose packet preview/editor is hidden on mobile.
**Verification:** The handoff, failover, and lifecycle group passed 59 tests, including explicit assertions that neither manual nor automatic handoff prompts the source worker, that target-side summarization completes before launch, and that the real target prompt contains no packet JSON. Focused UI and manager tests passed; targeted ESLint passed; `pnpm typecheck` passed; and `pnpm build:interface:web` passed.
**Prevention:** Never equate one worker stream with one conversation. Context reconstruction must use the durable conversation record and bounded visible entries from all replacement workers, while filtering transport, quota, and authentication failures from semantic summaries. Test both worker replacement and provider-failure tails.
**Skill/Doc Updates:** No general skill update was needed; the project-specific worker-stream and handoff architecture already establishes durable, append-only streams. This note records the missing reconstruction rule for future handoff work.
