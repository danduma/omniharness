# Handoff Evidence Is Not a Session Prompt

**Date:** 2026-08-26
**Context:** OmniHarness cross-CLI handoff preparation and target-session launch
**Symptom:** Target session `4dfa0a8df68e` received a 45,349-character initial message containing the complete internal handoff packet as formatted JSON. Internal hashes, provenance, workspace evidence, and dozens of file records dominated the visible conversation and became the provisional title.
**Root Cause:** `renderHybridHandoffSeed` treated the durable evidence packet as the target agent's prompt. Preparation gathered and serialized evidence but never ran a separate target-side synthesis step. Removing the invalid source-worker summary request exposed that missing stage instead of replacing it.
**Fix:** Preparation now spawns a disposable read-only instance of the selected target CLI/model/effort/account, asks it for a strict structured continuation report, validates the report, and destroys the temporary agent. The durable packet stores the generated advisory fields. The real target session receives bounded Markdown rendered from those fields and authoritative evidence, never raw packet JSON. Summary or cleanup failure blocks launch and emits typed lifecycle and surfaced-error events.
**Verification:** The exact historical packet now renders to 4,024 characters instead of 45,349 and contains neither `contentHash` JSON nor internal boundary tags. The handoff/failover group passed 59 tests, including target-summarizer cleanup, malformed-output refusal, named-event delivery, and compact target-seed coverage. `pnpm typecheck`, targeted ESLint, and `pnpm build:interface:web` passed.
**Prevention:** Keep durable machine evidence, model synthesis, and the human/agent continuation prompt as three separate layers. Never expose a storage envelope directly as product copy or a worker's initial message. Any model-generated handoff must identify which provider performs the synthesis, run before real-session creation, be validated, and have an observable failure path.
**Skill/Doc Updates:** The cross-CLI implementation plan and the target-summary design spec now state the three-layer flow and the no-raw-JSON invariant. No general skill update was needed because this is a project-specific control-plane contract.
