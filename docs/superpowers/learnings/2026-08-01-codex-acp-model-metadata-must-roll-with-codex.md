# Codex ACP Model Metadata Must Roll With Codex

**Date:** 2026-08-01
**Context:** OmniHarness Codex worker startup, model discovery, and ACP installation
**Symptom:** Starting a Codex worker with `gpt-5.6-sol` warned that model metadata was missing and fell back to generic metadata.
**Root Cause:** OmniHarness installed a June-built Rust ACP fork embedding Codex 0.124. The separately installed Codex CLI and the UI model list could advance, but the ACP process kept its own obsolete model registry. The fork had also drifted far enough from current Codex interfaces that simply changing its dependency tag produced extensive compile failures.
**Fix:** OmniHarness now uses the maintained `@agentclientprotocol/codex-acp` adapter, launches it with a separately rolling `@openai/codex` package, and injects the live `codex debug models` catalog into the managed Codex configuration. GPT-5.6 Sol is the default and model discovery respects Codex capability priority. The Unix and Windows installers compare both npm package versions and refresh them together; normal OmniHarness startup already invokes the ensure-only installer. The Docker image and scheduled compatibility workflow use the same official packages.
**Verification:** `pnpm typecheck`; `pnpm build`; targeted Vitest coverage for model ordering, metadata compatibility, saved-default migration, supervisor defaults, and installer rolling updates; live `codex debug models` catalog inspection; ACP protocol initialization smoke test; production restart and readiness check. The full suite passed 2,372 tests with two unrelated parallel-run failures that both passed when rerun alone.
**Prevention:** Treat the ACP adapter, Codex executable, model registry, and UI catalog as one compatibility surface. Never infer ACP model support from the standalone CLI version alone. Prefer the maintained app-server adapter and remote/live model discovery; keep a tested compatibility transform only for legacy adapters. Any future distribution change must verify the adapter version, Codex version, ACP initialization, and visible model order together.
**Skill/Doc Updates:** No general agent skill needed a project-specific rule. The durable system changes are the rolling installers, launcher, Docker image, scheduled compatibility workflow, managed model-catalog bridge, and this project note.
