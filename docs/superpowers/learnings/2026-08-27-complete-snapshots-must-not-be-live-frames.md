# Complete Snapshots Must Not Be Live Frames

**Date:** 2026-08-27
**Context:** OmniHarness browser-to-runner event transport, especially mobile clients
**Symptom:** A phone transferred roughly 6 GB after using OmniHarness for a short period. A live 12-second sample transferred 7,057,338 bytes.
**Root Cause:** The SSE route resent an uncompressed 926 KB complete catalog on selected-conversation updates. The catalog held 407 runs, 549 workers, session summaries, plans, and read markers even though only one selected run was changing. Separate five-second snapshot validation and two-to-five-second worker polling added packet churn despite resumable SSE and worker cursors.
**Fix:** Keep complete catalog delivery in snapshot bootstrap; project selected-run SSE frames to an explicitly partial catalog; omit the complete-catalog checksum from partial frames so unselected changes cannot falsely validate as current; gzip JSON and SSE with frame flushing; move validation polling to 30–60 second safety intervals.
**Verification:** The real runner measured 4,647 wire bytes over the same 12-second window after restart, a 99.93% reduction. `pnpm typecheck`, `pnpm build:interface:web`, focused HTTP and client tests, and `pnpm test:lifecycle` verified compilation, streaming flush behavior, scoped merging, cursor recovery, and lifecycle reconnects. One pre-existing event-route session-sync test remains red in isolation and is tracked separately from this transport change.
**Prevention:** Measure wire bytes, decoded frame sizes, frame cadence, and field-level payload weight before optimizing. Require every run-scoped stream to declare catalog completeness, require compression at the portable HTTP boundary, and treat polling as recovery rather than the normal transport when resumable events exist.
**Skill/Doc Updates:** Updated `docs/architecture/hot-path-responsiveness-and-resource-leaks.md` with the incident evidence and three permanent transport rules. No shared skill needed changes because the existing control-plane and client/server skills already require scoped completeness, cursors instead of bodies, resumable SSE, and bounded hot paths; the missing rule was project-specific enforcement at the HTTP boundary.
