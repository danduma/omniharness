# Edited Message Reruns Must Replay the Visible Prefix

**Date:** 2026-08-26
**Context:** OmniHarness direct-control conversation recovery and unified worker streams
**Symptom:** Editing and resending a user checkpoint left the old transcript visible in the UI, but Claude answered from a new session that had received only the edited text and therefore said it had no earlier context.
**Root Cause:** The edit path cancelled the saved worker and spawned a replacement with only the edited message. It neither rebuilt provider context from the run-wide append-only worker streams nor fenced late terminal snapshots emitted by cancelled turns. A first draft that replayed one source worker and repaired `done` once during spawn was also insufficient: visible history can span several workers, and stale completion can arrive after any one-time repair.
**Fix:** Direct edit fallback now uses the same run-wide chronological merge and per-worker superseded ranges as the transcript API, coalesces append-only streaming revisions by logical entry id, cuts that visible transcript strictly before the checkpoint, and appends the edited content as the next user prompt. Rewind advances every cancelled worker's durable turn generation, aborts its live local turn, and ignores status updates from cancelled or non-current workers with named and durable events. Every bridge-derived direct-turn writer—including completion, watchdog sync, snapshot persistence, fallback output, and restart reconciliation—carries the captured generation. The generation advance and JSONL append path share one per-worker output fence: an old write either lands before rewind and is superseded, or lands after it and is rejected under the lock with named and durable evidence.
**Verification:** The focused regressions were observed red before the fixes and green afterward. `pnpm vitest run tests/server/runs/rewind-superseded-branch.test.ts tests/conversations/direct-run-status.test.ts` covers multi-worker prompt reconstruction, streaming-revision coalescing, branch exclusion, generation advancement, durable/named events, and a deterministic late-output race at the persistence boundary. `tests/lifecycle/scenarios/direct-edit-context-replay.test.ts` exercises the edit route and stale-status event over HTTP/SSE with the unified JSONL stream. The transcript route tests, relevant server suite, TypeScript check, web-interface build, and lifecycle suite are completion gates.

**Concurrency follow-up:** A worker-level snapshot is not sufficient admission control for overlapping edits. A newer edit or retry can take its snapshot while the older recovery owns the conversation mutex but before that older recovery inserts its replacement worker. Recovery therefore also needs a synchronous run-level epoch: bump it before waiting for the mutex, register recovery provider turns against the captured epoch, abort registered turns on the next bump, and recheck the epoch inside the worker-turn gate before calling the provider. A stale recovery must also retire a worker created after the newer snapshot before persisting its provider session metadata; otherwise retry can select a session that never received the transcript replay. The regression pauses edit A before worker creation, starts retry B so its worker snapshot misses A's future worker, then proves A's worker is unselectable and only B delivers the visible prefix plus the edited prompt.
**Prevention:** Treat the transcript rendered to the user and the transcript used to reconstruct provider state as one run-wide, branch-aware authority. Recovery tests must inspect the actual provider prompt, assert discarded branches are absent across multiple workers, coalesce append-only revisions before prompt construction, and release stale lifecycle/output callbacks only after replacement delivery has begun.
**Skill/Doc Updates:** No general skill update was needed. The repository's lifecycle observability and unified worker-stream architecture documents already state the correct ownership model; the missing enforcement now lives in code and regression coverage.
