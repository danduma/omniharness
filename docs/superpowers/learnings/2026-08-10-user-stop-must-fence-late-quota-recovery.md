# User Stop Must Fence Late Quota Recovery

**Date:** 2026-08-10
**Context:** OmniHarness direct-control quota recovery and supervisor Stop handling; incident `7532d448e68f`.
**Symptom:** The user stopped a quota-waiting conversation, but a late quota callback opened a replacement recovery incident. When the reset time arrived, OmniHarness resumed the saved session and appended an automatic continuation prompt that the user had explicitly cancelled.
**Root Cause:** Supervisor Stop resolved the current recovery incident but did not mark a `cred-exhausted` worker as cancelled. Quota recovery also wrote `quota_waiting` without re-checking the persisted terminal run state, so an older asynchronous callback could regain ownership after Stop.
**Fix:** Stop now persists the cancelled run as an ownership barrier before cleanup and cancels `cred-exhausted` workers. Stop and every short quota mutation share a dedicated per-run recovery fence, separate from the broader conversation mutation chain that may await an external agent turn. Incident opening/escalation, wake scheduling, replacement reservation, and final run transitions therefore happen wholly before Stop or are refused wholly after it, without making Stop wait behind the turn it must abort. Conditional worker/run writes plus worker turn-generation fencing protect the external spawn/ask gaps. Most importantly, the automatic quota-resume prompt is abortable and is appended to the unified worker stream only after delivery succeeds; Stop during that turn leaves no sent-message entry, intervention, or `worker_prompted` event. Refusals emit both `recovery.refused` and the durable `quota_recovery_refused` execution event.
**Verification:** The new lifecycle regression was observed failing with `state: "quota_wait"` before the fix and passing with `state: "ignored"` afterward. Focused quota, wake, Stop, bridge-fence, resume, failover, and lifecycle suites passed 115 tests, including quota handling nested inside the long-lived conversation mutation while Stop completes independently. The runner TypeScript project, targeted ESLint, and `git diff --check` passed. The full serialized lifecycle run passed 27 of 28 files; the remaining pre-existing shared-database FK cleanup scenario passed immediately in isolation.
**Prevention:** Treat a user-owned terminal state as a fencing token, not merely a final UI status. Every callback and timer must re-check persisted authority immediately before mutation, and state transitions that can race with Stop must use conditional writes. Lifecycle tests must reproduce the late callback itself and assert the refusal over the production SSE surface.
**Skill/Doc Updates:** No general skill update was needed. `docs/architecture/lifecycle-observability-and-testing.md` Rule 11 already requires terminal user actions to retire recovery ownership; this change makes the quota path conform to that existing rule and adds the missing regression.
