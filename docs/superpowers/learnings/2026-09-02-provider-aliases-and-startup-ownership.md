# Provider Aliases Need Identity Proof And Startup Resources Need One Owner

**Date:** 2026-09-02
**Context:** OmniHarness Claude ACP launch, portable HTTP streaming, and direct-run recovery for session `76d5d121fe24`
**Symptom:** A requested `claude-opus-5` worker was rejected because Claude ACP reported the valid alias `opus[1m]`. Each rejection left an unregistered ACP child, a compressed client disconnect could crash the runner, and the resulting `lost` worker was later rewritten as `running` while its recovery incident was resolved as healthy.
**Root Cause:** OmniHarness compared provider and canonical model strings instead of verifying identity through the provider's model metadata. The launch acquired resources before manager registration but had no cleanup owner for failures in that interval. Disconnect cancellation destroyed gzip with a synthetic error while concurrent producer/consumer promises were not jointly observed. Finally, recovery scans treated `lost` as neither active nor unhealthy, so it fell through to healthy/running projections.
**Fix:** Explicit Claude selections now resolve the reported value against unambiguous family/version metadata and accept only an already-running verified identity; empty choices, absent values, duplicate aliases, and contradictions inside one option all fail closed. The manager claims child/client/link ownership before handshake awaits, rejects duplicate in-flight names, waits through TERM/KILL cleanup, and transfers a prewarm only when the pool explicitly accepts it. Compressed responses destroy gzip without an error, release drain waits on close, and await producer and consumer together. Selected and background sync both route `lost` through recovery, while incident creation takes a SQLite write lock before its identity check.
**Verification:** The red-green cycle was captured in focused model, process-cleanup, pool-ownership, gzip-backpressure/disconnect, recovery classifier, background sync, concurrent incident, and lifecycle tests. The widened impacted suite passed 316/316 tests, and `pnpm test:lifecycle` passed 59/59 tests across 38 files. Repository-wide `pnpm typecheck` remains blocked only by an unrelated pre-existing error in untracked `tests/app/conversation-transcript-retention.test.ts:27`; the shared, runner, and interface TypeScript project checks completed before that final test compilation step.
**Prevention:** Keep canonical intent separate from observed provider identity; accept aliases only with unique, internally consistent metadata proof. Establish ownership before the first failure-prone await and require explicit acceptance at every ownership transfer. Model expected disconnects as cancellation and settle blocked backpressure waiters as well as concurrent promises. Never interpret a durable loss state as absence of evidence, and make idempotency decisions under the persistence layer's write lock.
**Skill/Doc Updates:** Updated `docs/architecture/lifecycle-observability-and-testing.md` with the provider-identity, pre-registration ownership, compressed-disconnect, and durable-lost-worker invariants. No global skill change was needed because the project-specific lifecycle architecture document is the authoritative rule for this control plane.
