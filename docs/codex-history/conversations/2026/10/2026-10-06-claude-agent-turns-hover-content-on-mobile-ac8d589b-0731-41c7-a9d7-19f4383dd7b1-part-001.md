## Claude · 2026-10-06T06:44:25.787Z

The agent-message toolbar never appears on a phone, and there's no way to get it to show. At `src/components/Terminal.tsx:2409-2411` it's `opacity-0 pointer-events-none` and only becomes visible through `group-hover/agent-message` or `focus-within`. Tailwind v4 applies `hover:` variants only on devices that can hover, so touch screens never trigger it. `focus-within` doesn't help either, because the buttons ignore taps while they're hidden.

**My recommendation is 3 dots on touch devices.** The codebase already uses this pattern for worker output (`src/components/home/ConversationMain.tsx:563-587`): desktop keeps the hover copy button, and mobile gets a `MoreHorizontal` dropdown with 40px tap targets.

Why not show the toolbar all the time:
- It's an absolute overlay at `bottom-0 left-0` on narrow screens, so leaving it visible would cover the last line of each message.
- Fixing that means putting it back in the layout, which brings back the 28px gap under every message that the comment at line 2396 says was removed on purpose.
- You'd also have copy, every action, the model label and the time under every message. In a long transcript of short agent messages, that's a lot of repeated clutter.

How I'd build it:
1. **Detect touch with `@media (hover: none)`, not a width breakpoint.** An iPad with a trackpad can hover fine, and a narrow desktop window can still hover. The worker card uses `md:`; I'd switch it to the same media query so the two stay consistent.
2. **Hover devices stay exactly as they are now.**
3. **On touch, put one small ⋯ button under each finished message, inside the layout and right-aligned.** It shouldn't overlay the text. One small row costs much less space than a full toolbar.
4. **The menu holds copy and the other actions.** Actions that already have submenus (`MessageActionMenu`) become `DropdownMenuSub` entries. The model and time go in a non-clickable header at the top of the menu.

If you want a middle ground, show the full row only on the last agent message of a turn (which is how Claude's mobile app works) and use ⋯ on earlier ones. That adds a bit of complexity, so I'd only do it if you copy from the latest reply much more than from older ones.

I haven't changed anything yet. Should I go ahead with the 3-dots version?

## Claude · 2026-10-06T06:51:59.994Z

On phones and other touch devices, every finished agent message now has a ⋯ button underneath it. Desktop and anything that can hover works exactly as before. I haven't committed anything.

Tapping ⋯ opens a menu with:
- the model and time as a small header at the top
- **Copy**, with the usual "Copied" notice next to the button
- the message's other actions, where any that already had a dropdown open as submenus

The rest of what changed:
- **Touch detection.** I added a `touch` Tailwind variant (`@media (hover: none)`) in `src/interface/styles/globals.css`. It goes by whether the device can hover, not screen width, so an iPad with a trackpad still gets the hover toolbar.
- **The hover toolbar** (`src/components/Terminal.tsx`) is now `touch:hidden`, since it could never be revealed or tapped there anyway.
- **The ⋯ button** is a new `AssistantMessageTouchMenu` component. It sits under the message instead of on top of it, so it can't cover the last line of text. That costs one short row per message, but only on touch devices.

**Checks:**
- All 341 UI tests pass, including a new render test (`tests/ui/terminal-assistant-touch-menu.test.tsx`) and a new check in `sidebar-layout.test.ts`.
- The interface typecheck and eslint are clean.
- The repo-wide `tsc --noEmit` reports 18 errors, all in `tests/server/acp/runtime-client.test.ts` and `tests/server/workers/stream-gap-backfill.test.ts`, which I didn't touch.
- In a production build, the `touch:` rules come out after the base utilities, so they correctly override `hidden` and `flex`.
- I haven't seen it on an actual phone or in a touch-emulated browser. That needs a logged-in conversation that has agent messages, so please look at it on your phone.

The worker-output copy menu in `ConversationMain.tsx` still decides by width (`md:`) rather than by touch. I left it alone because existing tests pin that behavior. Switching it to `touch:` would make the two menus behave the same, if you want that.
